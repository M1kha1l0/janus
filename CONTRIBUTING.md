# Руководство по разработке (Contributing Guidelines)

Добро пожаловать в проект **Janus**! Чтобы поддерживать высокое качество кодовой базы и читаемую историю Git, все участники проекта следуют единым стандартам.

---

## 1. Соглашение по коммитам (Conventional Commits)

В проекте используется спецификация [Conventional Commits](https://www.conventionalcommits.org/). Сообщения коммитов формируются по следующему шаблону:

```text
<type>(<scope>): <краткое описание в повелительном наклонении>
```

### 1.1. Типы изменений (`type`)
* **`feat`** — новая функциональность или фича.
* **`fix`** — исправление ошибки или бага.
* **`perf`** — оптимизация производительности (уменьшение задержек, zero-copy, кэширование).
* **`refactor`** — переработка архитектуры или кода без изменения поведения.
* **`test`** — добавление или изменение юнит-тестов, бенчмарков.
* **`docs`** — документация (`README.md`, `ROADMAP.md`, комментарии Doxygen).
* **`build`** / **`ci`** — изменения в системе сборки `CMakeLists.txt`, GitHub Actions, тулчейнах.
* **`chore`** — рутинные задачи (обновление `.gitignore`, вспомогательные скрипты).

### 1.2. Области ответственности (`scope`)
Рекомендуемые области для проекта Janus:
* `sniffer` — парсинг TLS ClientHello, SNI и L7-протоколов.
* `tproxy` — интеграция с ядром Linux, `nftables`, `IP_TRANSPARENT`.
* `trie` — алгоритмы сопоставления доменов и префиксные деревья.
* `engine` — стейт-машина соединений, Racing Engine (Happy Eyeballs).
* `socket` — низкоуровневые RAII-обертки над сокетами и файловыми дескрипторами.
* `db` — интеграция с базой данных SQLite.
* `config` — парсер конфигурационных файлов.

### 1.3. Примеры правильных сообщений
* `feat(sniffer): add zero-copy TLS 1.3 ClientHello parser`
* `fix(tproxy): prevent file descriptor leak on connection timeout`
* `perf(trie): replace node allocation with flat memory vector`
* `test(engine): add integration test for 400ms fallback timeout`
* `docs(readme): add installation guide for Ubuntu Server`

## 2. Именование веток (Branch Naming)

Все новые изменения разрабатываются в отдельных тематических ветках:
* `feat/<название-фичи>` — для новой функциональности (например, `feat/tls-sniffer`).
* `fix/<описание-бага>` — для исправления ошибок (например, `fix/splice-deadlock`).
* `perf/<что-оптимизируем>` — для бенчмарков и оптимизаций.

Главная ветка: **`main`**.

## 3. Стандарты кода C++23

1. **Автоматическое форматирование:**
   Перед коммитом код **обязан** быть отформатирован с помощью `.clang-format`:
   ```bash
   clang-format -i $(git ls-files '*.cpp' '*.hpp')
   ```
2. **Компиляция без предупреждений:**
   Код собирается с флагами `-Wall -Wextra -Wpedantic -Werror`. Предупреждения компилятора трактуются как ошибки.
3. **Безопасность памяти:**
   * Запрещено использование «сырых» `new` и `delete`.
   * Системные ресурсы ядра (файловые дескрипторы, сокеты, пайпы) всегда оборачиваются в RAII-структуры.
4. **Обработка ошибок:**
   * В сетевом конвейере запрещено использовать C++ exceptions (`throw`) для штатных сетевых событий (разрыв связи, таймаут). Используется `std::expected<T, E>`.
